This tutorial deploys the `modal-devin` orchestrator for an existing Outposts pool.
At the end, sessions assigned to that pool can run inside Modal Sandboxes.

## Before you begin

You need:

- [uv](https://docs.astral.sh/uv/) and Python 3.11 or newer.
- A [Modal account](https://modal.com/docs/guide/modal-user-account-setup).
- A Devin organization with Outposts enabled.
- An Outposts pool ID such as `outpost_env-...`.
- A Devin token authorized to manage the pool and serve its sessions.

<Steps>
  <Step title="Install modal-devin">
    Run this in the Python project that will own the Modal application:

    ```bash
    uv add modal-devin
    ```
  </Step>

  <Step title="Configure Modal">
    If Modal is not already configured on this machine, run
    [`modal setup`](https://modal.com/docs/cli/latest/setup):

    ```bash
    uv run modal setup
    ```
  </Step>

  <Step title="Generate the application">
    Replace the sample ID with your pool ID:

    ```bash
    uv run modal-devin init my-pool \
      --pool-id outpost_env-... \
      --no-deploy
    ```

    If the expected [Modal Secret](https://modal.com/docs/guide/secrets) does not
    exist, the wizard prompts for the Devin token and offers to create it. The token
    is entered without echo and is not written to the generated Python file.

    The command writes `pools/my_pool.py`. It will not overwrite an existing file.
  </Step>

  <Step title="Check the prerequisites">
    ```bash
    uv run modal-devin doctor
    ```

    Resolve any reported credential, SDK, or Secret problem before deploying.
  </Step>

  <Step title="Deploy">
    ```bash
    uv run modal-devin deploy pools/my_pool.py
    ```

    The first deployment or first session can take longer while Modal builds the
    required images. Later starts reuse those build results when possible.
  </Step>
</Steps>

## Verify the deployment

Create or resume a Devin session and select the Outposts pool you deployed. Then
open the Modal application logs.

<Check>
  The deployment is working when a session invocation starts and its logs show the
  Devin worker processing your session.
</Check>

If no invocation starts, follow [Troubleshoot a deployment](/guides/troubleshooting#no-session-starts).
